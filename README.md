# re:plica — студия озвучки

Площадка для практики дубляжа. Автор загружает короткое видео и размечает реплики, исполнитель записывает собственный голос, администратор проверяет публикации. Подготовка сцены и запись озвучки — отдельные режимы.

В каталоге каждая исходная сцена появляется один раз. Внутри доступны опубликованные версии исполнителей: видео с выбранной озвучкой и скачивание WAV. Итоговая дорожка содержит только записанный голос; музыка и шумы оригинала в неё не входят.

## Запуск

Нужны **Node.js 24 или новее** и **PostgreSQL**. Локальная конфигурация использует PostgreSQL 17 в Docker Compose; приложение подключается через `DATABASE_URL`. FFprobe для проверки медиа устанавливается вместе с зависимостями; при необходимости можно указать собственный актуальный бинарный файл через `FFPROBE_PATH`.

```sh
npm ci
# Для новой установки; существующий .env не перезаписывается.
[ -f .env ] || cp .env.example .env
npm run db:up
npm start
```

Docker Compose открывает базу только на `127.0.0.1:54329`, сохраняет её в именованном Docker-томе и использует тестовые учётные данные из `.env.example`. Для внешнего PostgreSQL укажите собственный `DATABASE_URL`; запуск Compose тогда не нужен. `npm run db:down` останавливает локальную базу, сохраняя данные.

Откройте `http://localhost:3000`. Для записи микрофона на другом устройстве нужен HTTPS. Локальный `localhost` подходит для разработки.

Все регистрации создают обычного пользователя. Зарегистрируйте владельца, затем назначьте администратора в терминале сервера:

```sh
npm run admin -- owner@example.com
```

Команда использует тот же `DATABASE_URL`, что и сервер. Она работает только для уже зарегистрированного аккаунта. Старые администраторы при переносе данных сохраняют свои роли.

## Основной сценарий

1. `/workspace/create/`: загрузить видео длительностью до 15 минут.
2. `/workspace/segment/`: добавить персонажей, текст, начало и конец каждой реплики. Таймкоды имеют формат `ЧЧ:ММ:СС.ммм`; старый формат без миллисекунд тоже принимается. Изменения автоматически сохраняются через 1,5 секунды; есть ручное сохранение. Отправка на модерацию выполняется отдельно.
3. `/admin/`: проверить разметку и опубликовать сцену. Загруженные администратором видео тоже начинают с черновика. При возврате обязателен комментарий, который видит автор. Отправленные и опубликованные проекты закрыты для редактирования; сначала их нужно вернуть на правки.
4. `/workspace/dub/`: выбрать опубликованную или собственную размеченную сцену. Создаётся независимый проект с копией реплик и ссылкой на версию исходной сцены.
5. Перед записью можно нажать «Проверить микрофон»: откроется окно с уровнем сигнала и пробой до 5 секунд. Пробу можно остановить раньше и прослушать; интерфейс сообщает о тишине и перегрузке. После остановки, закрытия окна или ухода со страницы микрофон освобождается; при переключении вкладки проба останавливается. Проба остаётся только в этом окне, не отправляется на сервер и не заменяет дубль.
   Затем прослушать реплику, записать и проверить дубль. Во время записи, сохранения и сборки переключение реплик блокируется; остановка записи остаётся доступной. Индикатор уровня показывает сигнал микрофона во время записи.
6. После остановки дубль сохраняется в браузере (IndexedDB), затем отправляется на сервер. Каждая новая запись добавляется в список дублей реплики и выбирается для сборки; предыдущие записи остаются доступны. Кнопка «Слушать» позволяет сравнить варианты без изменения выбора, «Выбрать» назначает дубль для итогового WAV. Выбор сохраняется после перезагрузки. Существовавшая до обновления запись отображается как первый дубль.
   Если сеть недоступна, доступны повторная отправка и скачивание. Несохранённая запись восстанавливается при возвращении в этот проект на том же устройстве и в том же браузере. Повторная отправка той же записи после потери ответа сервера не создаёт дополнительный дубль. При недоступном IndexedDB копия остаётся только в памяти текущей страницы.
7. При необходимости убрать паузы по краям дубля: кнопка «Убрать тишину» находит границы автоматически и сохраняет их. Детектор оставляет по 80 мс вокруг найденного звука, внутренние паузы сохраняются; очень тихую запись без уверенно найденного сигнала он не меняет. Границы можно поправить вручную в секундах и нажать «Сохранить обрезку». Исходный файл не меняется; «Вернуть исходную» отменяет обрезку. Прослушивание, волновая форма и сборка учитывают сохранённые границы. После обрезки проверь начало и конец слов на слух.
   Сдвиг дубля задаётся с точностью до миллисекунд и определяет положение уже обрезанной записи в сцене. Если дубль всё ещё выходит за конец реплики, интерфейс предупреждает об этом; сборка предлагает обрезать выходящие части. У каждого варианта свои обрезка и сдвиг; новая запись начинает с нулевыми значениями. Если тайминги реплики изменены и сдвиг старого дубля больше не помещается в них, при выборе этого дубля сдвиг сбрасывается в ноль. Смена выбранного дубля или его обработки требует пересборки WAV.
8. Собрать моно WAV, 48 кГц / 16 бит, до 96 МБ; проверить его отдельно или вместе с видео и отправить на модерацию. Кнопка отправки доступна сразу после сборки.
9. После публикации версия появляется внутри исходной сцены. Исходная сцена должна быть опубликована. Для повторного редактирования нужен возврат на правки; изменения реплик или записей требуют новой сборки WAV.

Сервер проверяет реальные контейнеры и наличие аудио/видеодорожек, измеряет длительность и проверяет границы реплик. Заголовок типа медиа от клиента не используется при выдаче файлов. Медиа получают фиксированный тип, `nosniff` и ограничивающий CSP.

## Хранение и перенос старой установки

- **PostgreSQL**: пользователи, проекты, версии, решения модератора и сессии. Данные проектов хранятся в отдельных строках JSONB; есть индексы владельцев и исходных сцен. В реплике хранятся список дублей и идентификатор выбранного варианта. Все варианты учитываются в лимите хранения и включаются в резервную копию; удаление проекта удаляет их файлы.
- `DATA_DIR/uploads/`: видео, записи реплик и собранные WAV. База больше не хранится на локальном диске приложения.
- `lib/store.mjs`: пул соединений `pg`, транзакции и блокировка строк при изменениях.
- `migrations/001_initial.sql`: начальная схема. При запуске она создаётся идемпотентно под блокировкой PostgreSQL; несколько процессов могут безопасно запускаться одновременно.
- `scripts/migrate-legacy.mjs`: отдельный перенос данных из SQLite или исходных JSON-файлов.

`DATABASE_URL` обязателен. При недоступной базе сервер не запускается; переключения на SQLite или JSON нет. Учётной записи PostgreSQL нужны права на создание таблиц и индексов в выделенной базе приложения. Настройки TLS можно передать в строке подключения согласно требованиям провайдера; код не отключает проверку сертификатов.

Для переноса существующей установки остановите старое приложение, сохраните резервную копию папки данных и укажите **пустую** целевую базу PostgreSQL:

```sh
# DATABASE_URL и DATA_DIR берутся из .env или окружения.
npm run migrate:legacy -- /absolute/path/to/old-data
```

Если в папке есть `replica.sqlite`, импортируются её пользователи, проекты и активные сессии. Если SQLite-файла нет, импортируются `users.json` и `catalog.json`. Исходные файлы читаются без изменения. Весь импорт — одна транзакция; при ошибке частичного переноса нет. Повторный запуск после успешного импорта ничего не дублирует. Непустая целевая база без отметки прежнего импорта отклоняется.

Медиа не перемещаются: сохраните `DATA_DIR` со старой папкой `uploads` либо отдельно скопируйте её в новое постоянное хранилище. Старые JSON/SQLite после переключения не обновляются. Для отката нужна исходная копия всей папки данных.

Сохранение разметки требует актуального `revision`; сервер возвращает `409`, если проект изменился в другой вкладке. В транзакции строка проекта читается через `SELECT … FOR UPDATE`, поэтому конкурентные запросы не могут одновременно пройти проверку версии. Долгая загрузка файла проверяет версию повторно перед записью в базу. Ограничения объёма и создание дублей синхронизируются блокировкой строки владельца. Сессии действуют до 30 дней и переживают перезапуск приложения.

## Резервное копирование

Команда использует **pg_dump** в формате custom и копирует связанные медиа. Локальный `pg_dump` должен быть совместим с версией сервера; его путь можно задать через `PG_DUMP_PATH`.

Для полной копии остановите приложение (PostgreSQL оставьте работающим):

```sh
npm run backup -- /absolute/path/to/new-backup-directory
```

Если PostgreSQL запущен через предложенный Compose, можно использовать `pg_dump` внутри контейнера:

```sh
PG_DOCKER_SERVICE=db npm run backup -- /absolute/path/to/new-backup-directory
```

`PG_DOCKER_SERVICE` должен указывать именно на сервис PostgreSQL из `DATABASE_URL`. Команда передаёт учётные данные через окружение и выполняется из корня проекта.

Папка назначения должна быть новой и находиться вне `DATA_DIR`. Дамп базы и список медиа используют один экспортированный снимок PostgreSQL. Успешная копия содержит `replica.dump`, `uploads/` и файл `COMPLETE`. Если медиа менялись во время копирования и нужный файл исчез, команда завершится ошибкой без `COMPLETE`.

Для восстановления подготовьте пустую базу, остановите приложение и загрузите дамп:

```sh
# PGDATABASE — строка подключения к пустой базе восстановления.
pg_restore --dbname="$PGDATABASE" --no-owner --no-privileges --exit-on-error /path/to/backup/replica.dump
```

Затем скопируйте `uploads/` из копии в новый `DATA_DIR`, задайте `DATABASE_URL` восстановленной базы и запустите приложение. Для локального Compose можно передать дамп в `docker compose exec -T db pg_restore -U replica -d ИМЯ_ПУСТОЙ_БАЗЫ --no-owner --no-privileges --exit-on-error` через стандартный ввод.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | обязательна | Строка подключения к PostgreSQL |
| `DATA_DIR` | `./data` относительно проекта | Постоянное хранилище медиа |
| `TEST_DATABASE_URL` | обязательна для тестов | Отдельное подключение с правом CREATEDB |
| `PG_DUMP_PATH` | `pg_dump` | Путь к программе резервного копирования |
| `PG_DOCKER_SERVICE` | не задана | Сервис Compose для запуска pg_dump внутри PostgreSQL-контейнера |
| `PORT` | `3000` | HTTP-порт |
| `HOST` | `0.0.0.0` | Адрес прослушивания |
| `NODE_ENV` | не задана | В `production` cookie получает `Secure`; нужен HTTPS |
| `MAX_UPLOAD_BYTES` | 800 МБ | Максимальный размер одного видео |
| `MAX_USER_STORAGE_BYTES` | 5 ГБ | Лимит медиа одного пользователя |
| `FFPROBE_PATH` | бинарный файл зависимости | Собственная установка FFprobe |
| `TRUST_PROXY` | выключено | `1`: учитывать последний адрес `X-Forwarded-For` при ограничении входа; включать только за доверенным прокси |

Дополнительные ограничения: 100 проектов на пользователя, две одновременные загрузки, 500 реплик в сцене, 30 запросов входа/регистрации за 10 минут с одного адреса. При запуске за прокси без `TRUST_PROXY` пользователи могут делить общий лимит по адресу прокси.

`render.yaml` задаёт Node.js 24 и диск `/var/data`. `amvera.yaml` указывает постоянную папку `/data`. На Render и Amvera задайте `DATABASE_URL` своего PostgreSQL в переменных окружения/секретах; в Render-конфигурации эта переменная запрашивается при настройке. Для резервного копирования также нужен правильный `DATA_DIR`. PostgreSQL допускает несколько процессов приложения, но медиа пока остаются локальными: для нескольких серверов потребуется общее медиа-хранилище.

## Проверки

```sh
npm run db:up
npm test
npx playwright install chromium
npm run test:browser
```

Можно использовать установленный браузер, задав `BROWSER_EXECUTABLE_PATH`.

Серверные проверки выполняются на настоящем PostgreSQL: параллельная регистрация, сохранение во время загрузки, конфликты версий и откат транзакций, доступ к приватным проектам, проверка файлов, модерация, публичные версии, сессии и перенос SQLite/JSON. Браузерные — запись с синтетическим микрофоном, блокировку переключений, ошибку сети и восстановление записи после перезагрузки, сборку и отправку WAV, публичное воспроизведение, выход, автосохранение и таймкоды. Для обрезки проверяются границы и сохранность оригинала, восстановление после перезапуска, отмена и сброс при перезаписи, а также фактическое положение звука в собранном WAV. Детектор отдельно проверяется на тишине, тихом сигнале, внутренних паузах и нескольких аудиоканалах.

Тесты требуют `TEST_DATABASE_URL` с правом `CREATEDB`, создают отдельные базы `replica_test_*` и удаляют только их. `DATABASE_URL` приложения для тестов не используется. Проверка pg_dump/pg_restore включается командой `PG_DOCKER_SERVICE=db npm test`, остальные тесты идут и с внешним PostgreSQL. `test/fixtures/scene.webm` — синтетическое видео без стороннего контента.

## Ограничения

Реальные микрофоны, Safari/iOS и Android требуют отдельной проверки. Сборка WAV выполняется в браузере и может расходовать значительную память на длинных сценах. Экспорта готового видео, отделения оригинальной речи от музыки и совместной записи персонажей пока нет. Не реализованы восстановление пароля по почте, подтверждение адреса, объектное хранилище и распределённое ограничение запросов для нескольких серверов.
