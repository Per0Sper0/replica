# re:plica — студия озвучки

MVP площадки, где подготовка видео и озвучка разделены на два режима. Автор сначала загружает исходный ролик, размечает реплики в формате `ЧЧ:ММ:СС` и отправляет сцену на модерацию. После публикации сцену можно выбрать в каталоге. Автор также может озвучить собственную размеченную сцену. В режиме озвучки сайт по очереди показывает каждый размеченный фрагмент, позволяет прослушать оригинал, записать и переслушать дубль, а затем собирает записи в одну WAV-дорожку по исходным таймкодам.

## Запуск на компьютере

Нужен Node.js 20 или новее. В терминале из корня проекта:

```bash
npm start
```

Откройте `http://localhost:3000`. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

При первой регистрации созданный аккаунт получает роль администратора. Следующие аккаунты получают роль автора. Администратор может сразу добавлять сцены в общий каталог, проверять присланные проекты и публиковать их или возвращать автору. Не открывайте пустую инсталляцию в интернете, пока владелец не зарегистрировал первый аккаунт.

## Основные страницы

- `/` — публичный каталог сцен; озвучки опубликованных сцен можно прослушать рядом с репликами.
- `/register/` и `/login/` — создание аккаунта и вход.
- `/workspace/` — стартовая страница автора с выбором между загрузкой видео и озвучкой.
- `/workspace/create/` — отдельная страница только для загрузки исходного видео. После загрузки автор переходит к разметке.
- `/workspace/segment/` — отдельный редактор реплик и таймингов. Можно добавлять текст/персонажа и менять начало и конец фразы; время отображается как `ЧЧ:ММ:СС`. Запись голоса здесь не ведётся. «Сохранить в личный черновик» сохраняет приватную версию; отдельная кнопка отправляет сохранённую разметку на модерацию, а после одобрения она станет видна в каталоге.
- `/workspace/dub/` — пошаговая озвучка готовой сцены. Выбирай сцену из каталога или свою размеченную сцену. На каждой реплике доступны фрагмент оригинального видео, прослушивание оригинала и запись/перезапись голоса. После остановки записи свой дубль можно прослушать; следующая реплика открывается по кнопке. Когда все реплики готовы, браузер размещает их по таймкодам сцены и формирует один WAV-файл, который можно прослушать и скачать. Озвучку можно отдельно отправить администратору на модерацию.
- `/admin/` — редактор каталога и очередь модерации. Администратор открывает присланный клип, проверяет тайминги и прослушивает аудиофайл каждой реплики, затем публикует или возвращает проект на правки.

В публичном каталоге открой сцену и нажми **«Начать озвучку»**. Автору создастся отдельный проект-дубль с копией таймингов сцены; исходный проект и его разметка остаются самостоятельными. Для гостя потребуется войти или зарегистрироваться. Сборка WAV выполняется в браузере и ограничена сценами до 15 минут и итоговым файлом до 32 МБ. В дорожку входят записи автора, расставленные по таймкодам; само видео в этот WAV не включается.

## Карта файлов

| Файл / папка | Назначение |
| --- | --- |
| `server.mjs` | Node.js-сервер, JSON API, регистрация и вход, роли, загрузка файлов, проверка проектов и раздача видео с поддержкой перемотки. |
| `package.json` | Команды запуска и требование к версии Node.js; внешних npm-пакетов нет. |
| `render.yaml` | Необязательная конфигурация публикации на Render. Настраивает Node.js-сервис и отдельный диск для сохранения файлов. Создание сервиса и его оплата происходят только после подключения репозитория в Render. |
| `public/index.html`, `public/public.js` | Публичная главная страница и каталог. |
| `public/login.html`, `public/register.html`, `public/auth.js` | Экраны входа и регистрации. |
| `public/workspace-home.html`, `public/workspace-home.js` | Стартовая страница автора с выбором режимов и счётчиками проектов. |
| `public/upload.html`, `public/upload.js` | Страница загрузки видео; после загрузки открывает редактор разметки и показывает список личных видео. |
| `public/workspace.html`, `public/workspace.js` | Редактор разметки сцены: добавление реплик, таймкоды, сохранение личного черновика и отдельная отправка сохранённой версии на модерацию. |
| `public/dub.html`, `public/dub.js` | Студия озвучки с таймлайном дорожек оригинала и голоса, формами волны, записью реплик, сведением в WAV и отправкой дубля на модерацию. |
| `public/admin.html`, `public/admin.js` | Админский каталог, редактор таймингов и очередь модерации видео/озвучек. |
| `public/styles.css`, `public/enhancements.css`, `public/community.css`, `public/monochrome.css` | Общие стили сайта. Последний файл приводит палитру к чёрному, белому и серому и выравнивает общие отступы; знак и логотип re:plica находятся в SVG-файлах. |
| `public/assets/re-plica-logo.svg`, `public/assets/re-plica-mark.svg` | SVG-версии логотипа и фирменного знака для страниц и иконки сайта. |
| `data/users.json` | Аккаунты, роли и хеши паролей. Сам файл не хранит пароли в открытом виде. |
| `data/catalog.json` | Проекты, статусы модерации, роли и тайм-коды реплик. |
| `data/uploads/` | Видеофайлы и записи голосов. Папка не добавляется в Git. |
| `.gitignore` | Исключает локальные данные и секреты из Git. |

Папка `data/` появляется после первого запуска и должна сохраняться вместе с резервной копией. Если менять каталог хранения через переменную `DATA_DIR`, файлы будут создаваться именно там.

## Как получить ссылку, которую можно показать

Приложению нужен сервер Node.js: GitHub Pages не подойдёт, так как он не запускает `server.mjs` и не хранит загруженные видео. В репозитории подготовлен `render.yaml` для Render:

1. Отправьте код в GitHub-репозиторий `Per0Sper0/replica`.
2. Создайте аккаунт на Render и подключите этот GitHub-репозиторий.
3. В Render выберите создание нового **Blueprint** по `render.yaml`. Перед подтверждением проверьте план: конфигурация предусматривает платный Node.js-сервис `starter` и диск 5 ГБ.
4. Дождитесь публикации. Render выдаст адрес вида `https://имя-сервиса.onrender.com` — его можно открыть на другом устройстве и показать команде.
5. Сразу зарегистрируйте свой аккаунт на новом адресе: первый аккаунт станет администратором. После этого можно делиться ссылкой с другими; их аккаунты будут обычными авторами.

После подключения GitHub Render по умолчанию пересобирает приложение после каждого коммита, отправленного в связанную ветку. Так разработку можно продолжать в этой папке, отправлять изменения в GitHub и получать их на сайте автоматически.

Чтобы подключить собственный домен, купи его у регистратора, затем добавь в Render в `Settings → Custom Domains`. Render покажет DNS-записи для настройки у регистратора. Для `www` используется CNAME на адрес сервиса; для корневого домена — ANAME/ALIAS или A-запись в зависимости от DNS-провайдера. После этого нажми Verify в Render. Он автоматически выпускает TLS-сертификат и направляет трафик на HTTPS. См. [настройку пользовательского домена](https://render.com/docs/custom-domains) и [настройку DNS](https://render.com/docs/configure-other-dns).

Render Free может подойти только для короткого показа без сохранения загруженных файлов: бесплатные сервисы засыпают в простое и теряют содержимое файловой системы при остановке/перезапуске. Подготовленный диск сохраняет видео, но у него есть ежемесячная стоимость; проверьте актуальную сумму в Render перед подтверждением. Подробности — в [документации Web Services](https://render.com/docs/web-services), [документации persistent disks](https://render.com/docs/disks) и [тарифах Render](https://render.com/pricing).

## Границы этой версии

Это MVP для демонстрации, а не готовая публичная платформа. Сессии хранятся в памяти и завершаются при перезапуске сервера; нет восстановления пароля, подтверждения почты и защиты от спама. Видео, каталог и пользователи — файлы JSON и локальные файлы, рассчитанные на один экземпляр сервера, а не на большую командную нагрузку. Для реального запуска стоит перенести пользователей и проекты в базу данных, медиа — в объектное хранилище, добавить проверку загрузок, резервное копирование и более полное управление сессиями.
